Project OverviewProblem StatementManaging rental properties manually is fragmented, error-prone, and time-consuming. Property owners struggle to track multiple units, coordinate with tenants, collect rent, and maintain lease documents across disparate tools. Tenants, on the other hand, lack a unified digital portal to view their lease agreements, pay rent online, and communicate with their landlords. Traditional systems do not provide real-time visibility for administrators who need cross-platform oversight of users, properties, and payments.Proposed SolutionProperty Sync is a full stack MERN application with three role-based portals Admin, Owner, and Tenant that centralizes every aspect of property management. Owners can list properties, upload photos, assign tenants, and generate PDF lease agreements. Tenants can browse available listings, sign leases, and pay rent securely via Stripe. Administrators have a live dashboard with charts, user management, and automated downloadable reports. Email notifications are dispatched via SendGrid for key events such as new listings and lease changes.Target UsersProperty Owners / Landlords â€“ managing one or more rental unitsTenants â€“ renting residential or commercial propertiesSystem Administrators â€“ overseeing platform usage and generating reports4. Frontend Design DetailsComponent StructureThe frontend is split into three independent Create React App (CRA) applications: admin-frontend, owner-frontend, and tenant-frontend. Each follows the same layered hierarchy:pages/ â€“ route-level page components (e.g., DashboardPage, PropertiesPage)components/ â€“ reusable UI units grouped by domain (Auth/, Properties/, Dashboard/, Sidebar/, Topbar/)layout/ â€“ MainLayout wrapping persistent Sidebar and Topbarcontext/ â€“ AuthContext providing user state and token to the entire treeutils/api.js â€“ Axios instance with base URL and Authorization header injectionState Management ApproachAuthentication and user context are managed via React Context API (AuthContext) in all three frontends. Form state is handled locally using React useState in admin and owner apps, while the tenant app uses Formik + Yup for validation-heavy registration and payment forms. No Redux is used.API Integration StrategyEach frontend maintains a centralized Axios instance (utils/api.js or services/api.js) that automatically attaches the JWT Bearer token from localStorage to every request header. API calls are made inside async functions within component useEffect hooks or event handlers.8. Backend Design DetailsAPI ArchitectureThe backend follows a RESTful MVC pattern with the following module breakdown: routes/ define URL paths, controllers/ contain business logic, models/ define Mongoose schemas, and middlewares/ handle cross-cutting concerns.Authentication & Authorization StrategyJWT tokens are issued on login with the user role embedded in the payload. The protect middleware validates the token on every protected route. The requireRole() middleware enforces role-based access control (RBAC), ensuring for example that only owners can create properties and only tenants can initiate payments.Middleware Usageprotect â€“ decodes and verifies JWT; attaches user object to req.userrequireRole([roles]) â€“ checks req.user.role against allowed rolesupload (Multer) â€“ handles multipart/form-data for property images and avatarsExpress built-ins â€“ express.json() for body parsing, cors() for cross-origin supportError Handling ApproachAll controller functions are wrapped in try/catch blocks. Errors are returned as JSON objects with an appropriate HTTP status code (400 for validation, 401/403 for auth, 404 for not found, 500 for server errors). Mongoose validation errors bubble up naturally via the catch block.9.
